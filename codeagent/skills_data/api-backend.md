# واجهات برمجية

## التصميم
- أسماء الموارد جمع: `/api/orders` لا `/api/getOrder`.
- الفعل في طريقة HTTP: GET قراءة · POST إنشاء · PATCH تعديل جزئي · DELETE حذف.
- الرموز الصحيحة: 200 · 201 إنشاء · 400 مدخل خاطئ · 401 غير مصادق · 403 ممنوع · 404 غير موجود · 409 تعارض · 422 تحقق · 429 حد.

## التحقق من المدخلات — إلزامي
لا تثق بأي شيء من العميل. في FastAPI استخدم Pydantic بحدود صريحة:
```python
class OrderRequest(BaseModel):
    items: list[Item] = Field(min_length=1, max_length=100)
    note: str = Field(default="", max_length=500)
```
كل نص له `max_length`، وكل رقم له `ge` و`le`، وكل قائمة لها حد.

## الأمان
- لا تُرجع رسائل خطأ داخلية للعميل. سجّلها واعرض رسالة عامة.
- لا تضع أسراراً في الاستجابات — راجع كل حقل تُرجعه.
- حدّ طلبات على كل نقطة تكلّف مالاً أو موارد.
- CORS بقائمة نطاقات محددة، **لا `*` أبداً** مع مصادقة.

## الأخطاء
رسالة الخطأ تقول للمستخدم ماذا يفعل:
```python
raise HTTPException(404, "الطلب غير موجود. تحقق من الرقم أو راجع قائمة طلباتك.")
```

## قبل التسليم
- [ ] كل نقطة لها تحقق من المدخلات
- [ ] كل نقطة محمية بمصادقة إلا ما يجب أن يكون عاماً
- [ ] لا تسريب أسرار في أي استجابة
- [ ] اختبار لكل نقطة: نجاح · مدخل خاطئ · بلا صلاحية
