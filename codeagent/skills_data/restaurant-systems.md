# أنظمة المطاعم

## نموذج البيانات الذي لا ينكسر
```
Category → Item → Modifier/Option
Order → OrderItem (لقطة من السعر والاسم وقت الطلب)
```
**قاعدة حاسمة:** خزّن سعر واسم الصنف داخل `OrderItem` نفسه، لا مرجعاً فقط.
تغيير سعر المنيو بعد شهر يجب ألا يغيّر فاتورة قديمة.

## الأسعار
- **لا تستخدم float للمال أبداً.** استخدم أعداداً صحيحة بالقروش، أو `Decimal`.
- الدينار الأردني ثلاث خانات عشرية: 12.750 د.أ لا 12.75.
- خزّن الضريبة وقت الطلب. النسبة تتغير والفواتير لا.

## حالات الطلب
`draft → placed → confirmed → preparing → ready → delivered/served → completed`
مع `cancelled` من أي حالة قبل `completed`.
سجّل وقت كل انتقال — تقارير زمن التحضير تُبنى عليه.

## المنيو ثنائي اللغة
كل صنف: `name_ar` و`name_en`. الاسم العربي إلزامي والإنجليزي اختياري.
الفرز والبحث يجب أن يعملا بالعربية — انتبه لأل التعريف والهمزات.

## الطباعة الحرارية
- عرض 58mm ≈ 32 محرفاً، و80mm ≈ 48 محرفاً.
- الفاتورة العربية تحتاج معالجة اتجاه؛ اختبر على الطابعة لا على الشاشة.
- كل فاتورة: رقم متسلسل، تاريخ ووقت، تفصيل الأصناف، المجموع، الضريبة، الإجمالي، طريقة الدفع.

## الأوقات
خزّن كل شيء بـ UTC واعرض بتوقيت عمّان (+03، بلا توقيت صيفي).
اليوم المحاسبي في المطاعم لا ينتهي منتصف الليل — اجعله قابلاً للضبط (مثلاً 4 فجراً).

## قائمة تحقق
- [ ] لا `float` في أي حقل مالي
- [ ] `OrderItem` يحفظ السعر والاسم وقت الطلب
- [ ] كل انتقال حالة مسجّل بوقته
- [ ] الأسماء العربية مدعومة في البحث والفرز
