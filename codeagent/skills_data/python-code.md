# كتابة Python بجودة إنتاج

## قبل أن تكتب سطراً
1. `search_project` عن دالة أو صنف مشابه — اتبع أسلوب المشروع لا أسلوبك.
2. افحص `requirements.txt` أو `pyproject.toml`: **لا تستورد مكتبة غير مثبّتة**.
3. إن كان الملف موجوداً، `read_file` أولاً. لا تعِد كتابته من الصفر.

## قواعد غير قابلة للتفاوض
- `from __future__ import annotations` في أعلى كل ملف جديد.
- تلميحات الأنواع على كل دالة عامة.
- لا `except:` عارية ولا `except Exception` بلا سبب مكتوب. حدّد نوع الاستثناء.
- لا `print` للتصحيح في كود المكتبات — استخدم `logging`.
- المسارات بـ `pathlib.Path` لا بدمج نصوص.
- الملفات بـ `with open(...)` دائماً، ومع `encoding="utf-8"` صراحةً.
- لا قيم افتراضية قابلة للتغيير: `def f(x: list | None = None)` ثم `x = x or []`.

## البنية
- دالة تتجاوز 50 سطراً: قسّمها.
- أكثر من 5 وسائط: استخدم `@dataclass`.
- المنطق في دوال، والتشغيل تحت `if __name__ == "__main__":`.

## معالجة الأخطاء
اكتب رسائل تقول للمستخدم **ماذا يفعل**، لا ماذا حدث فقط:

```python
raise ValueError(
    f"الملف '{path}' غير موجود. تأكد من المسار أو شغّل: agent init"
)
```

## الاختبارات
أي دالة منطقية جديدة تحتاج اختباراً في `tests/test_<الوحدة>.py`:
- الحالة السعيدة، الحالة الحدّية، وحالة الخطأ.
- استخدم `tmp_path` للملفات و`monkeypatch` للبيئة.
- شغّل `run_tests` فعلياً بعد الكتابة. لا تفترض النجاح.

## قائمة تحقق قبل التسليم
- [ ] `validate_file` على كل ملف كتبته
- [ ] `run_tests` ونتيجتها خضراء
- [ ] لا مفاتيح ولا كلمات مرور في الكود
- [ ] الأسماء واضحة بالإنجليزية، والتعليقات بلغة المستخدم
